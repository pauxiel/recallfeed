### Spec 06: Inngest Workflows (`06-inngest-workflows.md`)

**Changes:**
- Database-error classification separated from AI errors

- AI errors caught and classified separately within AI operation try block
- Database query errors (getFeedItemByNoteAndType, getNoteById) outside AI catch block
- Proper error propagation: transient throws, permanent returns terminal status
- Obsolete `initialize-ai` step reference removed from acceptance criteria

**Key Contracts:**
- Database connection failures trigger Inngest SDK retry
- AI provider failures classified independently
- Transient AI (quota, timeout, unavailable) trigger retry
- Permanent AI (invalid response, empty result) return failed status
- Unclassified errors return terminal failed status after logging
- Constraint violation (23505) still treated as already_exists
